<objective>
Close the detection gap that let BUG-001 through. Today `npm run smoke` only uses fetch, and the unit tests run in Node, so nothing in Phase 1 ever loads the app in a browser. This plan adds one small real-browser step to the existing smoke script. The step uses `playwright-core` as a library and drives the Google Chrome already installed on the machine. It proves the badge reads "API ok", that the 60s poll fires while visible (G-01-2), and that the badge recovers after an outage (G-01-3). It also adds the favicon so the /favicon.ico 404 goes away (G-01-4).

Scope guard: this is NOT the Phase 6 Playwright suite (AUT-02/AUT-03). It adds no test runner, page objects, mocking layer or CI job, and no bundled browser download. It is one extra step inside `scripts/smoke-dev.mjs`, reusing that script's dev stack, free ports and CoinGecko stub.

Output: root devDependency `playwright-core@1.63.0`, the browser step in `scripts/smoke-dev.mjs`, `web/public/favicon.svg` and the icon link in `web/index.html`.
</objective>

## Phase Goal

ROADMAP Goal (verbatim): "A running skeleton (web + api) with CI and traceable logs, plus the wiki memory and test strategy every later phase builds on". User story framing: NOT AVAILABLE (the Goal line is not in As a / I want to / so that form; the planner did not invent one).

Why these choices (planner discretion, recorded in the wiki by plan 01-11):
- Browser check now rather than only documenting it: the escape analysis in the wiki finding names "no real-browser check" as the reason a blocker reached UAT. Phases 2-5 all add browser UI, so leaving the gap open for four more phases is a real risk.
- `playwright-core` with `channel: "chrome"`: Playwright's bundled Chromium cannot be installed on the dev machine (macOS 13), but installed Chrome works. The core package has no install scripts and downloads no browsers. It is the same library Phase 6 will build on, so nothing gets thrown away.
- Real time instead of Playwright's fake clock: a faked clock replaces the page's native timer functions with plain JavaScript functions that ignore the receiver. That would hide exactly this class of bug.
- Not a CI job: CI does not run `npm run smoke` today (REVIEW WR-03). The browser job arrives with AUT-02 in Phase 6. `npm run smoke` stays a local Entry Criterion.
