# Walking Skeleton — CoinGecko Paper Exchange

**Phase:** 1
**Generated:** 2026-09-15

## Capability Proven End-to-End

A developer runs one command (`npm run dev`) and a browser page served by the web app shows API health (API status + CoinGecko status) fetched cross-origin from the Fastify API, which reads and writes the upstream check in SQLite, returns an `X-Request-Id`, and writes a JSON log line carrying that same ID. Proven automatically by `npm run smoke` (plan 01-01) and continuously by GitHub Actions CI (plan 01-02).

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Repository shape | npm workspaces monorepo: `api/`, `web/` are workspaces; `qa/` is a plain Markdown folder in Phase 1 (becomes a workspace when Playwright lands in Phase 6); single root `package-lock.json` | One command for dev/test/lint (FND-01); single lockfile keeps `actions/setup-node` npm cache effective (RESEARCH Pitfall 2); `qa/` as docs-only avoids an empty package (RESEARCH A3) |
| Frontend framework | Vite 8 + React 19.3 + TypeScript; routing with `react-router` 8 component API (`BrowserRouter`, `Routes`, `Route`, `NavLink`, `Navigate`, `Outlet`) — verified exported by react-router 8.4.0 | Locked stack (PROJECT.md); later phases add `/trade/:pair` style routes into the D-01 shell instead of restyling |
| Styling | Plain CSS with custom properties (dark Binance-style tokens) in `web/src/styles/theme.css`; no CSS framework | Claude's discretion (CONTEXT.md); zero extra dependencies for a shell that later phases fill in |
| Backend framework | Fastify 5 + TypeScript executed by `tsx` (dev: `tsx watch`); `buildApp(deps)` factory in `api/src/app.ts` separate from `api/src/server.ts` (listen) so tests use `app.inject()` | Built-in pino logging and request-ID plumbing (RESEARCH Pattern 1/5); factory keeps every route testable in-process |
| Data layer | SQLite via `better-sqlite3` + Drizzle ORM 0.45; SQL migrations generated by `drizzle-kit generate` into `api/src/db/migrations/` (committed) and applied synchronously by `createDb()` before `app.listen`; first table `upstream_checks` | Locked stack (SQLite); boot-time migrate removes the dev-start race (RESEARCH Pitfall 1); `upstream_checks` gives the skeleton its real read + write and makes the D-05 5-minute health cache survive `tsx watch` restarts so saves never spend Demo calls |
| Auth | None in Phase 1. Phase 2 adds email + password with an httpOnly session cookie (AUTH-01..05); request logs already carry a `userId` slot (null until then) | Scope boundary (CONTEXT.md domain); the log contract is ready for per-user RCA |
| API contract conventions | JSON everywhere; every response carries `X-Request-Id`; errors use `{ error: { code, message, requestId } }` (D-09); CORS allow-list from `CORS_ORIGIN` with `X-Request-Id` exposed (D-07); no `origin: true` reflection | The request ID is the evidence thread UI error -> network tab -> log line -> bug report -> RCA |
| Observability | pino JSON to stdout and to a rotating file (pino-roll: daily or 10 MB, 14 kept); `api/logs/api.log` is a symlink to pino-roll's `current.log` so the D-06 path always resolves to the active file; one `request completed` line per request with `requestId, method, path, status, durationMs, userId`; outbound upstream calls get their own line; API key redacted (D-06/D-07/D-08) | RCA-01 evidence; pino-roll names files `api.<date>.<n>.log`, so the symlink preserves the locked path |
| Upstream integration | Server-only CoinGecko client (`api/src/lib/coingecko.ts`) sending `x-cg-demo-api-key`; base URL overridable via `COINGECKO_BASE_URL` (smoke test and later 429/stale tests point it at a local stub); `/ping` checked lazily with a 5-minute SQLite-backed cache and in-flight dedupe; missing key -> `not_configured` with no call (D-04/D-05) | Key never reaches the browser; health checks can never threaten the market-data call budget |
| Configuration | `api/src/config.ts` `loadConfig(env)`; `api/.env` loaded with Node's built-in env-file parser without overriding variables already set in the process; `web/.env` read by Vite (`VITE_API_URL`, `VITE_PORT`); `.env.example` files committed, `.env` ignored | No dotenv dependency; explicit env wins so the smoke test and CI stay deterministic |
| Testing | Vitest 5 in both workspaces (node environment); web components tested with `react-dom/server` `renderToStaticMarkup` + pure poller logic with fake timers (no DOM library); `scripts/smoke-dev.mjs` is the full-stack check; Playwright deferred to Phase 6 (AUT-02) | Fewest dependencies that still prove behaviour; smoke test exercises the real `npm run dev` |
| Tooling | TypeScript pinned to `~6.0.3` (research proposed 7.0.2, but `typescript-eslint@8.70.0` declares peer `typescript >=4.8.4 <6.1.0`, verified via `npm view` 2026-09-15); ESLint 10 flat config + typescript-eslint + eslint-config-prettier; Prettier 3 (`printWidth: 100`) scoped to code (docs folders ignored) | Lint and typecheck must both run in CI (FND-02); Prettier must never rewrite append-only `wiki/log.md` |
| CI | GitHub Actions on push + pull_request, Node 24, `actions/setup-node` npm cache; separate `lint`, `typecheck`, `test` jobs; concurrency group per ref; `GIT_COMMIT` = commit SHA | D-13; independent job statuses for reviewers |
| Repository visibility | Public `pyavchik/crypto-exchange` from plan 01-02 (immediately after the tracer); secret scan across all commits before first push | D-12 (one-way, already chosen by the user) |
| Deployment target | Phase 1: documented local full-stack run (`npm run dev`), proven by `npm run smoke` locally and CI on GitHub. Free hosting chosen in Phase 7 (STATE.md blocker) | No hosting decision is needed to prove the architecture |
| Directory layout | `api/src/{app.ts, server.ts, config.ts, routes/, lib/, db/{schema.ts, client.ts, migrations/}}`; `web/src/{main.tsx, App.tsx, components/, pages/, lib/, styles/}`; `scripts/` (smoke, wiki-lint); `qa/{TEST-PLAN.md, README.md, templates/}`; `wiki/` (LLM Wiki); `.planning/` (GSD) | Layer-by-concern inside each workspace; flat enough for reviewers to scan |

## Out of Scope (Deferred to Later Slices)

- Accounts, sessions, password hashing, per-user isolation (Phase 2)
- Market data endpoints, TTL market cache, stale fallback, curated pairs, charts (Phase 3)
- Balances, decimal math library, market orders, fees (Phase 4)
- Limit orders, fill-on-cross worker, order/trade history, P&L (Phase 5)
- Playwright suite, API test collection, exploratory sessions, RCA write-ups (Phase 6)
- Hosting provider, production CORS origins, seeded demo account, reviewer README (Phase 7)
- A shared types package between `api/` and `web/` (web mirrors the `/health` response type for now)

## Subsequent Slice Plan

Each later phase adds one vertical slice on top of this skeleton without altering its architectural decisions:

- Phase 2: A visitor signs up, logs in, stays logged in across refresh, logs out, and sees a private 10,000 USDT balance
- Phase 3: A user browses a live, rate-limit-safe markets table and a trade page chart served through the backend CoinGecko proxy
- Phase 4: A user market-buys and market-sells with decimal-safe balances and a visible 0.1% fee
- Phase 5: A user places, fills-on-cross and cancels limit orders and reviews order/trade history with P&L
- Phase 6: A reviewer runs API tests and a Playwright smoke suite in CI and reads exploratory notes, bug reports and RCA write-ups
- Phase 7: A reviewer clicks a public link, logs in with a demo account and finds every QA artifact within a minute
