<objective>
Turn the tracer's static markets table into the live, interactive one MKT-01 through MKT-05 describe:
it refreshes itself while you are looking at it, tells you how old its numbers are, lets you search
and sort them, and says plainly when the prices it is showing are delayed.

Purpose: two of the three pieces here have a known failure mode this project has already paid for
once. The poller is the exact code shape that shipped Phase 1's browser-only `Illegal invocation`
bug — a bug that passed every Node-environment unit test because Node's timer functions do not apply
the receiver check browsers do. Rather than writing a second poller exposed to the same risk, this
plan extracts the one implementation that was fixed and tested, so the markets poller inherits the
fix by construction and still carries its own strict-receiver suite. The search and sort logic is the
other: a comparator that subtracts possibly-absent numbers does not throw, it silently produces an
undefined row order, so the comparison rule lives in a pure, separately tested module with a
deliberately null-bearing fixture.

There is no DOM and no testing library in this workspace, and Phase 2 decided to keep it that way.
Everything here is therefore built as pure functions plus props-only views that
`renderToStaticMarkup` can exercise in every state; the interactive proof — real typing, real
clicking, a real 30-second timer — is 03-04's browser step and 03-05's manual cases, and that split
is deliberate rather than a coverage gap.

Output: `poller.ts`, `marketsPoller.ts`, `marketsTable.ts`, `StaleBanner.tsx`, and a markets page
wired to all four.
</objective>

   no server round-trip, and keeping this logic pure is the only way it can be tested at all in a
   workspace with no DOM. Named exports only.
   - `SORT_KEYS` is the readonly tuple of the three sortable columns MKT-03 names — price, 24h change

     and a direction.
   - `compareNullable(a, b, direction)` never subtracts values that might be absent. It returns zero
     when both are absent, places an absent value last in both directions, and otherwise compares
     numerically according to the direction. This rule exists because a naive numeric comparator does
     not throw on an absent value — it produces a not-a-number comparison and therefore an
     unspecified row order, which looks like a cosmetic sorting quirk while actually being
     non-deterministic output.

     nothing remains, and otherwise keeps pairs whose lowercased name or lowercased symbol contains
     it.

     own order, which is already the market-cap ranking the API applied upstream. Otherwise it sorts
     by the selected field through `compareNullable`, falling back to a lexicographic comparison of
     coin ids whenever the primary comparison is zero, so ties are deterministic rather than
     dependent on engine behavior.

     direction when the active key is selected again.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → browser payload → rendered table | Upstream-derived coin names and symbols cross here and are rendered for a user |
| user input → client-side filter | The search query crosses here; it is used only to compare strings in memory and never reaches a URL or a request |
| document visibility → poller | Browser lifecycle events drive whether network requests happen at all |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-15 | Tampering | coin names and symbols rendered in the table and the search results | medium | mitigate | Every upstream-derived string reaches the DOM only as a JSX text child; rendering markup from a string is gated against in the verification for both the page and the banner |
| T-03-16 | Information Disclosure | the search query | low | accept | D-46 keeps search entirely client-side over an already-fetched payload, so a query never reaches the server, a log line or a URL — there is nothing to disclose |
| T-03-17 | Denial of Service | poll pressure from an idle open tab | medium | mitigate | D-40's visibility gate stops polling entirely while the tab is hidden, and the server-side TTL cache is what actually bounds upstream calls regardless of how many tabs poll; the residual always-visible-tab case is carried as a documented risk in 03-05's test-plan update rather than silently ignored |
| T-03-18 | Repudiation | a delayed price shown as if it were current | high | mitigate | D-42: the banner renders from the payload's own stale flag, and the last-updated line reports the data's age rather than the request time, so a user can never mistake a failed refresh for a successful one |
