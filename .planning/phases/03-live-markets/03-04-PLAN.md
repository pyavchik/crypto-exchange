<objective>
Complete the user-facing phase: a visitor clicks a pair in the markets table, lands on its trade page,
and sees a real price chart they can switch between one day, one week and one month — and the whole
phase gets proven in Chrome, including the degraded path nobody can see from reading code.

Purpose: `lightweight-charts` is an imperative canvas library with no precedent anywhere in this
React tree — every existing component is a declarative render, and this one owns a canvas, its own
event listeners and a teardown call that has to actually run. The failure modes are specific and all
of them look fine until they do not: a missing teardown stacks a second live chart on every window
switch, a data effect wired to the chart's own effect recreates the whole chart on every poll tick,
and feeding the library millisecond timestamps renders an empty-looking chart rather than an
obviously broken one. `renderToStaticMarkup` cannot execute an effect or inspect a canvas, so the
strategy here is to push every one of those failure modes out of the component and into a DOM-free
controller that can be unit-tested against a fake chart factory, leaving the component as a shell and
leaving only "does a canvas actually appear and draw" for the browser step.

That browser step is also where this phase's two remaining claims get settled against reality rather
than assertion: that a forced upstream failure degrades to cached prices behind a visible banner, and
that the Demo key never reaches the browser.

Output: `lightweight-charts` installed, `priceChart.ts`, `PriceChart.tsx`, the trade page and its
routes, markets rows that link to it, and the final `npm run smoke` sections.
</objective>
