<objective>
Expand the tracer's backend into the two behaviors the markets slice deliberately left out: serving
the last good data when CoinGecko fails, and the per-coin, per-window price series the trade page
chart needs.

Purpose: stale serving is genuinely new logic, not a branch to copy. The existing ping service has no
last-known-good path at all — a failed check is simply recorded as "down" and returned as a fresh
result. DATA-03 requires the opposite for market data: degrade to slightly-old prices rather than
fail, make that degradation visible as data on the payload rather than as a separate endpoint, and
never let it happen silently on the server, because an RCA has to be able to reconstruct which
upstream failure caused which stale serve. The chart endpoint is where this phase's open-proxy risk
lives: a coin id arriving in a URL path is the first client-controlled string this project has ever
interpolated toward an upstream, so it is validated against the curated list before anything is
fetched or cached.

Output: the last-good fallback inside the keyed cache, the stale-serve log call site, `getChart`,
the millisecond-to-second point conversion, and `GET /api/markets/:id/chart`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/markets/:id/chart` | The first client-controlled string this project interpolates toward an upstream crosses here |
| API → CoinGecko chart endpoint | The Demo key and a coin id cross here; only ids the API itself already listed may cross |
| failed upstream → cached value → browser | On failure the previously cached value is re-served; its provenance and age must travel with it |
| stale-serve event → log file | The reason an outage degraded the app crosses here and is what an RCA reconstructs from |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-08 | Tampering | `GET /api/markets/:id/chart` path id | high | mitigate | Two layers, both tested: a Fastify params pattern restricted to lowercase letters, digits and hyphens, then an equality check against the cached curated list before any upstream call; tests assert zero chart upstream calls for fifty fabricated ids |
| T-03-09 | Denial of Service | chart cache key space | medium | mitigate | Because validation precedes `getChart`, a rejected id never reaches the cache, so the key space is bounded by the curated list times three windows — it cannot be grown by enumeration (D-45) |
| T-03-10 | Denial of Service | upstream outage degrading every client at once | medium | mitigate | D-41's last-good fallback: the app degrades to slightly-old prices instead of failing, and the fallback is deterministically testable through the base-URL stub seam rather than a real outage (D-51) |
| T-03-11 | Repudiation | a silent stale serve | medium | mitigate | D-43: every stale serve emits one warning carrying the request id, the resource key, the upstream reason and the data's age, so a user-visible delayed-prices banner can be traced to the exact upstream failure that caused it |
| T-03-12 | Tampering | a malformed upstream body entering the cache | medium | mitigate | Both mappers validate shape and throw; a validation failure is classified as an upstream failure, so a malformed body is never written to the cache and instead triggers the last-good fallback |
