<objective>
Deliver the phase's tracer slice: a logged-out visitor opens `/markets` in a real browser and sees a
live, Binance-like table of the curated top-20 pairs — price, 24h change, 24h volume, market cap —
served from a server-side TTL cache, with the CoinGecko Demo key proven absent from every request
the browser makes.

This is one vertical slice wired through every layer the phase touches: the generalized keyed cache,
the CoinGecko markets client, a new public Fastify route, the app wiring, the FE fetch client, a new
formatting module, the markets page and the route swap in `App.tsx` — proven end to end by the real
browser `npm run smoke` step before any expansion work (stale serving, chart, search, sort, polling)
is layered on top.

It is split into three commits purely for context budget: Task 1 is the API half, Task 2 is the
browser half, Task 3 is the real-browser proof. The slice is not done until Task 3 is green.

Purpose: three of this phase's highest-risk facts sit directly on this path and none of them can be
settled by reading code. CoinGecko rejects the USDT ticker as an upstream currency code (verified
live, 400), so D-36's "quoted in USDT" has to be modelled as a USD upstream call plus a stated
display convention that Phase 4's order math will inherit. The existing cache in
`api/src/lib/coingecko.ts` is shaped for exactly one resource and has to be generalized before a
second resource exists, not after. And success criterion 3 — the key never reaching the browser — is
only a real guarantee if it is measured against live browser network traffic. Proving all three on
one path first means an architectural dead end costs one commit, not five.

Output: `keyedCache.ts`, `marketData.ts`, `GET /api/markets`, `format.ts`, `fetchMarkets`, the
`/markets` page, and an extended `npm run smoke` browser section.
</objective>

  <behavior>
    - `createInFlightRegistry().run(key, fn)` invokes `fn` once when five callers race on the same key, and all five resolve to the same value.
    - The registry runs `fn` twice for two different keys raced concurrently — a miss on one key never queues behind a miss on another.
    - After the promise for a key settles, a later `run` on that key invokes `fn` again (the slot clears on both success and rejection).
    - `createKeyedCache().resolve(key, ttl, fetcher)` calls the fetcher on the first call and returns `stale: false` with a `fetchedAt` from the injected clock.
    - A second `resolve` before the TTL elapses returns the cached value without calling the fetcher again; one millisecond past the TTL it calls the fetcher again.
    - `toMarketPairs` maps a live-shaped `/coins/markets` array to `MarketPair[]`, deriving `pair` as the uppercased symbol joined to the quote symbol by a slash.

1. `api/src/lib/keyedCache.ts` (new) — the generalization 03-PATTERNS.md flags as a refactor rather
   than a copy-paste. Two named exports, no default export, matching the `lib/` convention.
   - `createInFlightRegistry()` returns an object with a single `run<T>(key, fn)` method backed by a
     `Map<string, Promise<unknown>>`. If the map already holds a promise for the key, return it cast
     to `Promise<T>`. Otherwise call `fn()`, attach a `finally` that deletes the key, store the
     resulting promise in the map and return it. The registration into the map must happen
     synchronously, in the same turn as the `fn()` call and before any `await` — that ordering is the
     entire point of the primitive, and it is what T-01-17 already fixed once for the ping resource.
     Put a doc comment at the function naming T-01-17 and D-39 as the origin of the rule.
   - `createKeyedCache<T>({ now = Date.now } = {})` holds a `Map<string, CacheEntry<T>>` plus its own
     registry, and exposes `resolve(key, ttlMs, fetcher)` and `peek(key)`. `resolve` reads the entry;
     when one exists and `now() - entry.fetchedAt < ttlMs` it returns that entry with `stale: false`
     and performs no call. Otherwise it delegates to `registry.run(key, ...)` with a fetcher wrapper
     that, on success, writes `{ value, fetchedAt: now() }` into the map and returns the entry, then
     returns `{ value, fetchedAt, stale: false }`. A rejecting fetcher rejects out of `resolve` in
     this plan — 03-02 adds the last-good fallback branch and its `onStale` hook, and the D-41 stale
     behavior belongs to that plan, not this one.
   - Add a one-line comment at the cache map noting that an in-memory store does not deduplicate
     across processes, so a future horizontally-scaled deployment would multiply the upstream call
     rate by the instance count.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API (cross-origin, public) | Unauthenticated market-data requests cross here; no credential accompanies them by design (D-44) |
| API → CoinGecko | The Demo key crosses here as a request header and must cross nowhere else (DATA-01) |
| CoinGecko → API → browser | Upstream-controlled strings (coin name, symbol) and numbers cross two boundaries before rendering |
| API → log file / stdout | Request URLs and upstream outcomes cross here into a file a bug report may quote publicly |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information Disclosure | the CoinGecko Demo key | critical | mitigate | Header-only transport in `marketData.ts`, never a query parameter; every upstream call server-side; Task 3 asserts against live browser traffic that no request leaves localhost and none carries the key in a URL, header or body |
| T-03-02 | Information Disclosure | `marketData.ts` log fields | high | mitigate | The log line carries only upstream name, URL, status, duration and outcome — no headers, no deps object, no key — extending `coingecko.ts`'s D-08 discipline; Task 3 greps the whole smoke log file for the key |
